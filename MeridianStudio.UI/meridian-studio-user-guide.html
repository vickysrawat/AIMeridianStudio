🚀 First Run Setup

Prerequisites

  • Node.js 20+ — for the Angular frontend
  • .NET 10 SDK — for the API backend
  • A modern browser (Chrome, Edge, Firefox)

Start the Application

Start the API server

Open a terminal in the MeridianStudio.API/ folder and run:

dotnet run --project MeridianStudio.API.csproj --launch-profile http

The API will be available at http://localhost:5000. You should see startup logs in the terminal.

Start the UI

Open a second terminal in the MeridianStudio.UI/ folder and run:

npm start

Wait for "Application bundle generation complete", then open http://localhost:4200 in your browser.

Verify the connection

The workspace header should show a green model-status indicator. If it shows a connection warning, confirm the API is running on port 5000.

Optional: Add LLM API Keys

Without keys the Heuristic Engine handles all requests. To enable live AI responses:

cd MeridianStudio.API
dotnet user-secrets set "LLM:Gemini:ApiKey" "AIza..."
dotnet user-secrets set "LLM:Groq:ApiKey"   "gsk_..."
dotnet user-secrets set "LLM:Claude:ApiKey" "sk-ant-..."
⚠️
Restart the API server after setting secrets for the changes to take effect.

🔍 Module 1 — Trends Discovery

Trends Discovery performs AI-powered market research. Enter industry keywords and receive a curated set of solution opportunities, domain context, and competitor insights.

[Screenshot: Trends Discovery panel with keyword input, domain label, and 5 solution cards]

Basic Research Workflow

Enter keywords

Type one or more industry keywords into the search field (e.g. "healthcare AI", "fintech compliance", "e-commerce fulfillment"). The system auto-detects the industry vertical.

Submit the research request

Click Discover (or press Enter). The Model Status bar shows which AI provider is processing the request.

Review the results

Results appear in three sections:

  • Domain — auto-detected industry vertical and sub-domains list
  • Solution Items — 5 prioritised opportunities, each with urgency, difficulty, value scores, rationale, real-life value, and integration steps
  • Competitor Insights — 4 competitor analyses with feature gap and strategic playbook
Select a solution to continue

Click any solution card to carry it forward to the Architectural Blueprinter module.

Advanced Options

ActionHow toEffect
Load more results Click Load More Returns 5 additional solutions not already shown (bypasses cache)
Regenerate from scratch Click Re-run Evicts server cache and generates a completely fresh result set
Refine with feedback Type in the feedback field before re-running AI incorporates your feedback into the next generation

Understanding Solution Scores

FieldRangeMeaning
Urgency1–10How time-sensitive the market need is
Difficulty1–10Implementation complexity (higher = harder)
Value1–10Strategic and business value of the solution
💡
Solutions with high Value + low Difficulty are your best quick-win opportunities. High Urgency + high Value indicates a strategic priority worth immediate investment.

🏗️ Module 2 — Architectural Blueprinter

Given a selected solution, the Blueprinter generates a complete system architecture with five structured sections, all formatted as rendered Markdown.

[Screenshot: Blueprint panel showing Core Scenario, Base Topology with ASCII diagram, and Database Schemas tabs]

Generating a Blueprint

Carry a solution from Trends Discovery

Select a solution card in Trends Discovery. Its name and ID populate automatically in the Blueprinter panel. Alternatively, enter a solution name and ID manually.

Confirm the domain (optional)

The domain detected during research is pre-filled. You can override it to change the architectural context.

Click Generate Blueprint

Blueprint generation typically takes 5–15 seconds with live models, or under 1 second with the Heuristic Engine.

Navigate blueprint sections

Use the section tabs to explore the five blueprint components:

Blueprint Sections

📖

Core Scenario

300+ word narrative describing the business context, user journeys, and integration goals of the solution.

🗺️

Base Topology

ASCII architecture diagram showing services, data flows, and infrastructure components.

🗄️

Database Schemas

SQL CREATE TABLE statements for the primary data entities, with indexes and foreign keys.

📡

Endpoint Manifest

Full REST API specification in Markdown table format — method, path, request/response shapes.

🛡️

Resilience Strategies

Multi-model cascade configuration, circuit breaker patterns, retry policies, and fallback strategies.

ℹ️
The Blueprint ID is required when generating documents in Document Studio. Copy it from the blueprint header before switching modules.

⚙️ Module 3 — Execution Pipeline

The Execution Pipeline simulates the engineering work required to build a solution component. It produces real-time progress logs, a C# 13 code template, and a 0–100 progress score.

[Screenshot: Execution Pipeline showing task name input, real-time log stream, progress score gauge, and code template panel]

Running a Task

Enter the task name

Type a descriptive engineering task, e.g. "Build FHIR Ingestion Pipeline" or "Implement AML Transaction Scoring Service".

Fill optional context fields

Systemic Value — the business impact of this task. Estimated Effort — sprint estimate (e.g. "3–5 sprints"). Context — additional detail for the AI.

Click Execute Task

The log panel streams timestamped events as the Meridian Task Executor processes the request. Logs typically span 8–12 seconds of simulated execution time.

Review outputs

Once complete, the panel shows a progress score (0–100), a status badge (Completed), and a generated C# 13 service class template ready to copy.

Understanding the Execution Logs

Each log entry has the format: [{elapsed}ms] {level} — {message}

LevelMeaning
INFONormal progress — initialisation, parsing, processing stages
SUCCESSTask completed — final line always shows the progress score
WARNNon-blocking issue encountered — fallback was used
ERRORA stage failed — partial output may still be available

Set the document title

Choose a template type

💬 Module 5 — Prompt Studio

Prompt Studio generates developer-ready LLM handoff prompts for any component in your system blueprint. Each prompt includes structured directives, a context summary, and quality gates.

[Screenshot: Prompt Studio with component name field, target LLM selector, and generated prompt with directive sections]

Generating a Prompt

Name the component

Enter the exact component or service name from your blueprint, e.g. "FHIR Ingestion Service", "AML Transaction Scorer".

Select the target LLM (optional)

Choose Claude Sonnet, Gemini, or Groq. The prompt is optimised for the selected model's strengths and context window.

Add context (optional)

Paste relevant snippets — schema, endpoint list, tech constraints — to make the generated prompt more specific.

Generate and hand off

Copy the Prompt Text and paste it directly into your chosen AI tool. The Directives block appears separately for quick reference.

Prompt Structure

Every generated prompt contains:

  • Header — component name, target LLM, generation timestamp
  • Context Summary — role of the component in the overall system
  • Functional Requirements — numbered list of capabilities to implement
  • Directives — named quality gates (COMPLETENESS, SAFETY, PERFORMANCE, etc.)
  • Output Format — expected deliverable structure

📊 Module 6 — Executive Slides

Executive Slides exports your workspace findings as a PowerPoint presentation (.pptx) suitable for stakeholder delivery. Slides are generated from the current workspace state — research results, blueprint highlights, and document extracts.

[Screenshot: Executive Slides module with slide preview thumbnails and Export to PPTX button]

Exporting Slides

Ensure workspace data is populated

Run Trends Discovery and (optionally) generate a Blueprint before exporting. The slides module pulls from whatever is currently in the workspace.

Open Executive Slides

Click the Executive Slides tab. A slide preview shows the generated deck.

Click Export to PPTX

The browser downloads a .pptx file generated client-side via pptxgenjs. No server round-trip required.

📡 Model Status Panel

The Model Status panel (visible in the workspace header) shows real-time LLM routing events via a persistent SSE connection. You never need to refresh — it updates automatically.

Status Indicators

IndicatorMeaning
🟢 ConnectedSSE stream established; ready to receive events
🔵 AttemptingOrchestrator is calling a specific AI provider
✅ SucceededProvider returned a valid response
🟠 Failed / RotatingProvider returned an error; promoting to next tier
⚡ Fallback ActiveAll live providers failed; Heuristic Engine is responding

Model Cascade Order

  1. Gemini 2.5 Flash — fastest, lowest cost, attempted first
  2. Groq llama-3.3-70b — high-capacity fallback
  3. Claude Sonnet 4.6 — premium quality fallback
  4. Heuristic Engine (Offline) — always available, deterministic
ℹ️
The modelUsed value shown on each result card tells you exactly which tier produced that specific response.

⚙️ Domain Settings

Domain Settings lets you configure workspace-level preferences that carry across modules.

Available Settings

  • Default Industry Vertical — pre-selects a domain so you don't need to enter keywords every time
  • Preferred Model — hint the cascade to start from a specific provider (if configured)
  • Workspace name — label for the current session's exported artefacts
⚠️
Domain Settings are currently workspace-scoped and reset when the browser tab is closed. Persistent user profiles are planned for a future release.

🔧 Troubleshooting

Application won't load

  • Confirm both the API (http://localhost:5000) and UI (http://localhost:4200) servers are running
  • Check the terminal for startup errors — the most common cause is a port conflict
  • Try a hard refresh (Ctrl+Shift+R) to clear cached Angular assets

Model Status shows "Disconnected"

  • The API SSE endpoint (GET /api/events/model-status) is unreachable
  • Restart the API server — it may have crashed or timed out
  • Check that no proxy or firewall is blocking long-lived HTTP connections

Research returns "Heuristic Engine (Offline)" when I have API keys

  • Ensure you restarted the API server after setting secrets with dotnet user-secrets set
  • Verify the key is valid and has remaining quota with the provider
  • Check the Model Status panel — the failed event will name which provider errored

Blueprint or Document generation is very slow

  • Live model calls (Gemini, Groq, Claude) take 5–20 seconds depending on load and quota
  • If the cascade has rotated to Claude Sonnet, it generates longer, higher-quality output — extra latency is expected
  • To skip live models entirely, remove API keys so the Heuristic Engine responds immediately

PowerPoint export is empty or malformed

  • Ensure Trends Discovery has been run at least once before exporting slides
  • Try re-running research, then re-open Executive Slides
  • Check the browser console for pptxgenjs errors

Scalar UI shows errors

  • Open http://localhost:5000/openapi/v1.json directly — if this returns an error, the API itself has a startup problem
  • Review the API terminal for exception stack traces

❓ Frequently Asked Questions

Does MeridianStudio send my data to external servers?
Only when live AI API keys are configured and used. In offline/Heuristic mode all processing is local. When live keys are active, your keywords and solution names are sent to the respective provider (Gemini, Groq, or Claude) to generate responses.
Can I use MeridianStudio without an internet connection?
Yes — the Heuristic Engine runs entirely locally and covers all 9 industry verticals. Simply do not configure any LLM API keys and the app operates fully offline.
Why do I always get the same research results for the same keyword?
Results are cached server-side per keyword. Click Re-run to evict the cache and regenerate from scratch, or use Load More to fetch additional items that avoid duplicates.
How many solution items can I get from one research request?
Page 1 always returns exactly 5 items. Each click of Load More adds another 5 unique items. There is no hard cap, but results may become less differentiated after 20–30 total items.
Can I generate multiple blueprints from the same research session?
Yes — click different solution cards to generate separate blueprints. Each blueprint has its own unique ID and can be used independently in Document Studio and Prompt Studio.
What does the progress score in the Execution Pipeline mean?
It is a simulated 0–100 score representing how completely the Meridian Task Executor was able to address the engineering task. A score of 100 means all task phases completed without errors. The score does not reflect real code quality — it reflects the completeness of the simulated execution model.
Which AI model writes the best blueprints?
The primary model for blueprint generation is Groq llama-3.3-70b, which produces detailed ASCII topology diagrams and SQL schemas efficiently. Claude Sonnet tends to produce more narrative-rich content when it's used as a fallback. Both are significantly richer than the Heuristic Engine for custom domains.
How do I use the generated C# code templates from the Execution Pipeline?
Copy the template from the code panel and paste it into your .NET project. The templates target C# 13 with .NET 10 patterns (sealed records, primary constructors). They are starting scaffolds — they require project-specific wiring, dependency injection registration, and testing before production use.
Is there a way to save my workspace between sessions?
Currently, workspace state is held in-memory and resets when the browser tab is closed. Export your results before closing — use the PPTX export for slides, copy Markdown from Document Studio, and copy code templates from the Execution Pipeline. Persistent session storage is planned for a future release.
Can I run multiple industry verticals in one session?
Yes — simply change the keyword in Trends Discovery and run a new search. Each search is independent. You can have results from different verticals visible in the same workspace by using Load More with different keyword searches, though the interface treats the latest research result as the active context for Blueprinter and Document Studio.
